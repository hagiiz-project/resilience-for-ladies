# 02. 相談文面の差し替え（Word / Googleドキュメント → knowledge.json）

相談の「中身」はすべて **`knowledge.json`** にあります。画面（`index.html`）とは分離しているので、**文面を直しても、アプリの作りには一切触りません。**

いま入っているのは仮データです。監修済みの原稿ができたら、この手順で差し替えます。

---

## knowledge.json の形

```json
{
  "version": "2026-08-05",
  "contacts": {
    "police": { "label": "身の危険", "number": "110", "tel": "110" },
    "ss":     { "label": "性暴力被害", "number": "#8891", "tel": "8891" },
    "dv":     { "label": "DV相談", "number": "#8008", "tel": "8008" },
    "yori":   { "label": "よりそいホットライン", "number": "0120-279-338", "tel": "0120279338" }
  },
  "chunks": [
    {
      "id": "period",                    // 内部ID（英数字・重複しない）
      "section": "避難所での困りごと",       // 分類（表示には未使用・整理用）
      "title": "生理用品が手に入らない",      // 相談テーマの名前
      "keywords": ["生理", "ナプキン", "タンポン"],  // ← この語が入力に含まれると当たる
      "urgent": false,                   // true にすると「先に窓口を出す」緊急扱い
      "empathy": {                       // 共感の一文（返しの種類ごとに3通り）
        "soft":     "そっと寄り添う言い方",
        "plain":    "はっきり教える言い方",
        "together": "一緒に考える言い方"
      },
      "steps": [                         // 次の行動（上から順に。情報量で表示数が変わる）
        "まずやること",
        "次にやること"
      ],
      "contacts": ["yori"],              // つなぐ窓口（contacts のIDを並べる。空でも可）
      "body": "この相談の説明文（検索・将来のAI用。表示はされません）"
    }
  ]
}
```

### 3つのポイント

- **`empathy` は3通り**：利用者が選んだ「返しの種類（そっと／はっきり／一緒に）」で切り替わります。3つとも埋めてください。
- **`steps` の数**：利用者の「情報量」設定で、上から 2／3／5 件が表示されます。**大事な行動ほど上**に置いてください。
- **`keywords` が命**：この語が入力文に含まれると、そのテーマに当たります。**言い換え・話し言葉・ひらがな**も入れると取りこぼしが減ります（例：「怖い」だけでなく「こわい」も）。緊急テーマは特に厚めに。

---

## やり方 その1：手で直す（原稿が少ないとき）

`knowledge.json` をテキストエディタで開き、`chunks` の各項目を書き換えるだけです。JSONの記法（`"`で囲む・末尾のカンマに注意）を崩さないようにします。編集後、[JSONの文法チェッカー](https://jsonlint.com/) に貼って `Valid` が出れば安全です。

---

## やり方 その2：Word原稿から自動生成（原稿が多いとき）

Word（.docx）を決まった見出しで書いておくと、スクリプトで `knowledge.json` に変換できます。同梱の `tools/build_knowledge_from_docx.py` を使います。

### Word原稿の書き方（テンプレート）

各テーマを、次の見出し・ラベルで書きます（見出しスタイルは不問、行頭の記号・ラベル文字で判定します）。**テーマの区切りは行頭の「■」**です（「# 」でも可）。同梱の `content-template.docx` を開くと、この形の空欄がすでに用意されています。

```
■ 生理用品が手に入らない            ← 行頭「■」でテーマ開始（「# 」でも可）
分類: 避難所での困りごと
緊急: いいえ
キーワード: 生理, ナプキン, タンポン, ショーツ, 経血
共感-そっと: 言い出しにくいことを、よく書いてくれました。……
共感-はっきり: 衛生用品の不足は、避難所運営で改善が遅れる項目です。……
共感-一緒に: まず切り分けましょう。置いていないのか、頼みにくいのか。……
行動: 物資の担当者に「衛生用品が必要です」と伝える。
行動: 女性の担当者を探す。いなければ、置いてほしいと求めてよい。
行動: まとめて受け取れないか聞く。
窓口: yori
説明: 避難所で生理用品が不足しやすい、という背景の説明。……

# つきまとわれている                ← 次のテーマ
緊急: はい
……
```

- `行動:` は複数行OK（上から順に並びます）。
- `窓口:` は `contacts` のID（`police / ss / dv / yori`）をカンマ区切りで。
- `緊急:` は `はい`／`いいえ`。

### 変換コマンド

```bash
pip install python-docx
python tools/build_knowledge_from_docx.py 原稿.docx knowledge.json
```

`knowledge.json` が上書き生成されます。あとは GitHub に上げ直すだけ。**次に開いた人から新しい文面が反映されます。**

---

## やり方 その3：Googleドキュメントから自動更新（運営がコードに触りたくないとき）

元の設計どおり、Apps Script を使えば「Googleドキュメントを直す → `knowledge.json` が自動更新」という運用も作れます。内部テストの段階では **その1／その2** で十分なので、必要になった段階でご相談ください（`docs/03` の Apps Script と同じ仕組みで実装できます）。

---

## 差し替え後のチェックリスト

- [ ] JSONが `Valid`（文法エラーなし）
- [ ] `empathy` の3種すべてが埋まっている
- [ ] 緊急テーマ（性暴力・DV等）の `urgent` が `true`、`contacts` が入っている
- [ ] 想定される話し言葉が `keywords` に入っている（取りこぼし確認）
- [ ] 実機で数パターン入力して、意図どおりのテーマに当たる
