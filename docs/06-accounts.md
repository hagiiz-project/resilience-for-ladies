# 06. 参加者アカウント（自己登録・ログイン）

テスターが**自分でID・パスワードと属性を登録**し、次回から**ログイン**して使う仕組みです。相談ログに**参加者ID**が入るので、スプレッドシート上で「ID ↔ 属性 ↔ 相談内容」を後から紐づけられます。

## 何が起きるか（画面の流れ）

1. 最初の画面は **ログイン**（初回は台帳が空なので **新規登録** から）。
2. **新規登録**：自分で決めた `ID`・`パスワード` と、`性別`・`年代`・`性格(MBTI傾向)` を登録。
3. 以降はチャットへ。相談を送るたびに、スプレッドシートの「ログ」に**参加者ID付き**で記録。
4. 設定メニューから **ログアウト**（別IDで入り直し）ができます。

## この方式の位置づけ（正直な範囲）

個人環境で本格的な認証基盤は用意しない前提の、**「本番同様の登録・ログイン体験」**です。安全側に倒すため、次の設計にしています。

- **パスワードは平文で保存しない**：端末内で SHA-256 ハッシュ化して照合します。
- **パスワードはスプレッドシートに送りません**：シートに出るのは **ID＋属性だけ**。
- **属性は最小限**（性別・年代・性格）に限定し、暴露リスクを下げています。
- **サイレント運用**：名前・メール・電話・IPは取得しません。

**限界（本物の認証との違い）**：照合は各端末の中で行うため、アカウントは**登録した端末に紐づき**ます（別端末では同じIDで入れません）。テスターが自分の端末で使う内部テスト用途では十分ですが、厳密な本人確認・なりすまし防止・端末間ログインが必要になったら、Supabase/Firebase などの認証基盤を足す必要があります（別途相談）。

## スプレッドシートの構成（自動で3シート）

`docs/03` の Apps Script（更新済み）が、必要なシートを自動で作ります。

- **参加者**：`登録日時 / 参加者ID / 性別 / 年代 / 性格(MBTI)` … 登録時に1行。
- **ログ**：`受信日時 / 参加者ID / 相談の種類 / 年代設定 / 返しの種類 / 情報量 / 本文` … 相談ごとに1行。
- **感想**：`受信日時 / 感想・改善`。

**紐づけ方**：分析時は「ログ」と「参加者」を**参加者IDで結合（VLOOKUP等）**すれば、どの属性の人がどんな相談をしたかが分かります（属性は「参加者」に1回だけ持たせ、「ログ」には重複させない正規化。露出も最小）。

## 設定（2か所だけ）

1. `index.html` の `CONFIG.REQUIRE_ACCOUNT` を `true` に（既定でtrue）。`false` にすると登録なしの匿名運用に戻ります。
2. `CONFIG.LOG_ENDPOINT` にスプレッドシートの受け口URLを設定（`docs/03`）。登録情報と相談ログはここへ送られます。未設定でもアプリは動きますが、集約はされません。

Apps Script は `tools/appscript_sheet_logger.gs`（更新済み）をそのまま使えば、`register` と `log` を自動で振り分けます。

## プライバシー運用の注意（繊細な窓口のため）

- テスターへ「ID・属性・相談内容を匿名で記録する」旨を事前に伝える。
- **推測されやすいIDにしない**よう案内（本名・生年月日などを避ける）。
- 10代の参加者を含む場合、収集する属性は最小限のまま増やさない。
- 保存先スプレッドシートの共有は運営メンバーだけに限定。テスト終了後の削除方針を決めておく。
